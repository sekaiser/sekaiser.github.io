As I’ve been learning Rust, I’ve been looking for easy and practical projects to get my head around basic concepts and increase my syntax muscle memory. One of the more common tasks is to load data from different sources, like text files, or more structured data like JSON.

So it got me thinking, how would parsing a fairly complex JSON look like in Rust? Luckily, it is not this difficult!

This post is a demonstration of using serde_json to parse JSON in Rust. For this purpose, I am using the athletics data set of the Olympic Games Tokyo 2020. The goal is to find the five most successful countries and print them.

Org-mode publishing showcase

I chose an excerpt of the athletics data set, because its a bit more complex than a typical hello world example. The data set is deeply nested, contains a lot of data and different object types and to make things even more interesting some data, such as the countryObject field appears to be inconsistent.

In order to print the requested information, we need to parse the JSON data and extract the fields medalType and the countryObejct as shown above.

The code

Serde_json allows us to map JSON data to enums and this is what we are going to do. Since we also want to count the different types of medals we define a struct called MedalCount.

Let's add indexing operations

Thanks to serde_json we can easily map the medal data to our enum. But how can we use this information to our advantage once we want to count how many gold, silver and bronze medals a country won? After all, we would like to keep the actual counting as readable as possible and for this, the mapping logic needs be stored elsewhere.

Luckily, Rust offers two traits that can be used for indexing operations: Index and IndexMut. By implementing both traits we can map a variant of our class enum to the respective field in our MedalCount struct as shown below.

As far as I know, serde_json does not support mapping of nested data to struct via some form of dot notation. Luckily, if data is not mapped to a predefined struct than the JSON data can still be deserialized into a Value, which then allows us to get the nested data we want.

Follow the medal pipeline

One worked example, from five awards to a ranked medal table. This small, invented dataset is not the Olympic results; the values below illustrate one pass through the article’s extraction, counting, and ranking steps.

Example input · 5 awards

1. Extract country and medal

Flatten the events into five awards. Read countryObject.name when the country is an object there; otherwise use country.name.

2. Count medals per country

Group the five awards into three countries, incrementing the matching medal counter for each award. Japan’s two gold awards become one row.

3. Rank and take the top five

Compare gold first, then silver, then bronze. Kenya’s one gold places it ahead of Italy’s silver and bronze. There are only three countries, so taking the top five retains all three; no tie-breaker is needed.

Conclusion

This post demonstrates the usage of serde_json in order to parse nested JSON data. The article also briefly covers how to use traits in order to keep the code organized and the logic clean. Serde is very powerful and I encourage people who are interested in Rust to take a look at it.
